# Glossary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A glossary that reinforces the book's vocabulary. `<Define>` marks where a term is introduced, a glossary page lists every term in reading order, and in later chapters the first mention of each term gets a dotted underline with a hover or tap definition.

**Architecture:** Terms are a `glossary` content collection (one YAML file per term). Pure helpers in `src/lib/glossary.ts` find `<Define>` sites in chapter bodies, check them against the collection, and work out reading order. `loadGlossary()` in `src/lib/data.ts` fails the build when they disagree. The `MarkdownContent` override post-processes each chapter's rendered HTML with `markMentions()` (hast) to wrap first mentions, and renders one shared popover component when anything was marked.

**Tech Stack:** Astro 7 + Starlight 0.42, Bun (`bun test`), `hast-util-from-html`, `hast-util-to-html`, `unist-util-visit`.

**Spec:** `docs/superpowers/specs/2026-10-31-glossary-design.md`

## Global Constraints

- Use Bun, never pnpm or npm: `bun add`, `bun test src`, `bun run test:dist`.
- UI order: Starlight built-in components first, then plugins, then hand-rolled. Every `<style>` has `/* ui-exception: <reason>; expires: YYYY-MM-DD */` on the next line. Use `2027-01-31` as the expiry date.
- Internal links in components go through `withBase(import.meta.env.BASE_URL, path)`.
- Draft chapters stay off the public site. In a production build (`import.meta.env.PROD`), a term whose defining chapter has `draft: true` is not on the glossary page and is not marked anywhere. In `bun dev`, everything shows.
- The author edits `src/content/docs/part-1-primitives/what-is-a-model.mdx` concurrently. Re-read it right before each edit. Change only the words named in Task 2. Never commit it. The author commits it.
- User-visible copy: plain words, sentence case, serial commas, straight quotes, no em dashes.
- Glossary ids are kebab-case file names in `src/content/glossary/`.

## Review Focus

1. The HTML round trip in `MarkdownContent` can break the next-token island, Expressive Code copy buttons, or Mermaid diagrams. A chapter with no eligible terms must come back byte-for-byte unchanged, and one with terms must keep `<astro-island>` and `<pre>` intact (Task 4 tests both).
2. A term inside a link, heading, code, `<dfn>`, or island must not be marked, or the page gains nested links and broken code (Task 4 test).
3. "token" must not match inside "tokenizer", and a `skip` phrase like "error message" must not be marked (Task 4 tests).
4. A term defined in a draft chapter must not leak into production: not on the glossary page, not marked, and no link to the draft (Task 1 unit test, Task 3 dist test).
5. On a phone, the first tap on a mention must show the definition and not navigate. Escape and a tap outside must close it. Keyboard focus must show it (Task 5 manual check).

export type DefineSite = { term: string; chapter: string; index: number };
export type Mentionable = { id: string; forms: string[]; skip: string[] };
export type GlossaryGroup = { chapter: string; terms: Array<{ term: Term; site: DefineSite }> };

export function mentionableIn(chapter: string, terms: Term[], sites: DefineSite[], order: string[], published: Set<string>): Mentionable[];

- [ ] **Step 1: Build the component**

It renders one popover: `<div id="glossary-popover" role="tooltip" hidden>`. Inside are a `<p>` for the definition and a Starlight `LinkButton` labeled "Open in glossary" (`variant="secondary"`, `icon="right-arrow"`), with its `href` set by the script. The marked terms go in `<script type="application/json" id="glossary-terms">`.

The client script:
- **On `(hover: hover)` devices:** `mouseenter` and `focus` on a mention show the popover below it, and `mouseleave` and `blur` hide it. The button is hidden, and a click follows the link.
- **On other devices:** the first tap on a mention calls `preventDefault()` and shows the popover with the button. A tap outside hides it.
- **Everywhere:** Escape hides it, and the mention gets `aria-describedby="glossary-popover"` while the popover shows.

The styles live in one `<style is:global>` with a ui-exception on the next line: `/* ui-exception: Starlight has no tooltip or popover component, and no plugin provides one; expires: 2027-01-31 */`. They cover:
- `.glossary-mention`: `text-decoration: underline dotted`, inheriting the text color.
- the popover's position, max width, border, radius, and background, using `--sl-color-*` tokens so both themes work.
